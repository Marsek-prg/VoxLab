# Проверка VoxLab

## Portable 0.1.1

Изменена структура поставки: единственный пользовательский EXE в корне, зависимости в `App`, данные в корневой `Data`. Нативный apphost проверен запуском из другой рабочей папки: 9/9 UI/bridge-проверок прошли, настройки созданы рядом с EXE, `App/Data` не создана. Движок обработки звука не изменялся; ниже сохранены результаты его проверки в 0.1.0.

## Проверка движка 0.1.0

Проверено локально на Windows x64 4 ноября 2026 года. Это результаты конкретной сборки и устройств, а не обещание для любого ПК.

## Выполнено

- Release-сборка WPF/WebView2: **0 ошибок, 0 предупреждений**.
- Ядро DSP: **22/22 проверки**. Проверены валидность пресетов, NaN/Infinity и границы параметров, сдвиги −12/−7/+4/+7/+12 полутонов с сохранением длительности, частота чистого тракта, ограничение пиков, абсолютный mute, bypass, закрытие/открытие гейта, сжатие, задержанный импульс эха, фильтрация НЧ в радио, смена параметров, тишина, 44,1/96 кГц, нестандартные блоки и ограниченные выделения памяти.
- Windows-аудиоинфраструктура: **8/8** — предварительное заполнение, переполнение и оборачивание кольцевого буфера, границы записи в массив, параллельный producer/consumer, точный WAV, ошибка открытия файла, повторный Stop/Dispose и недопустимый маршрут.
- Синтетический benchmark: 3 секунды сигнала с pitch/robot/echo/chorus/reverb обработаны за **71 мс** в первом запуске на этой машине. Это скорость офлайн-вычисления, **не сквозная задержка аудио**.
- Реальный WASAPI: **Nady USB Microphone**, 48 кГц, 3 секунды, выход принудительно заглушён. Первый тест чистого тракта: 0 underruns, 0 overruns, ошибок нет.
- Отдельный тест смены чистого пресета → женский тембр → робот и завершения WAV: **2,96 с**, mono 48 кГц 32-bit float, корректный заголовок; все отсчёты нулевые из-за mute. 1 underrun при смене алгоритмической задержки, 0 overruns. Это известный кратковременный переход при переключении pitch, а не скрытый результат.
- Native bridge/UI: **9/9** — выбор «Робот» реально обновляет параметры C#, слайдер передаёт высоту 3,5, форма создаёт пользовательский пресет, mute/bypass меняют состояния движка. Дополнительно проверено сохранение клавиатурного фокуса после выбора пресета, избранного, категории и выключателя эффекта.
- Снимки WebView2 при обычном и минимальном окне: данные загружены, 16 пресетов, горизонтального переполнения документа нет.
- Браузерная проверка: выбор пресета, слайдер с клавиатуры, создание пользовательского пресета и навигация стойки работают. Предпросмотр явно помечен и не имитирует работу микрофона.
- Расширенный прогон реального приложения: **19/19** проверок, включая все 16 пресетов, четыре перезапуска, WAV >20 секунд с нулевыми отсчётами, остановку и недопустимый маршрут. Во время измеренных стабильных фаз 0 underruns / 0 overruns. Счётчики сбрасываются при перезапуске; это не отменяет известного перехода при включении pitch.
- Проверка NuGet direct/transitive зависимостей не обнаружила известных уязвимостей на момент выпуска. Это проверка базы advisories, а не гарантия отсутствия уязвимостей.
- Оригинальный архив VB-CABLE проверен SHA-256. Установщик имеет действительную Authenticode-подпись издателя; Windows 10 catalog подписан Microsoft Windows Hardware Compatibility Publisher. Драйвер в ходе проверки не устанавливался.

## Нагрузка

Финальный повторный прогон portable EXE с .NET **10.0.13** на данном ПК: 12 логических процессоров, WASAPI 48 кГц, буфер 40 мс. CPU ниже — доля всей машины, сумма процесса приложения и его WebView2-процессов. Звук принудительно заглушён; вычисления эффектов продолжаются. Значения не являются гарантией для другого оборудования. Машиночитаемый результат: [performance-results.json](performance-results.json).

| Сценарий | CPU | Private bytes | Сумма working set |
| --- | ---: | ---: | ---: |
| Окно открыто, звук выключен, 10 с | 0,09% | 264 MiB | 440 MiB |
| Pitch + robot + drive + chorus + echo + reverb и запись, 20 с | 2,34% | 265 MiB | 458 MiB |
| Та же обработка в трее, 20 с | 0,24% | 262 MiB | 457 MiB |
| После 16 пресетов и 4 перезапусков, 10 с | 1,21% | 272 MiB | 471 MiB |
| Звук снова выключен, 10 с | 0,17% | 284 MiB | 468 MiB |

Сумма working set повторно учитывает общие страницы процессов; private bytes — выделенная приватная память, а не точное количество физической RAM. WebView2 составляет значимую часть расхода памяти. До оптимизации частых обновлений в простое измерялось 0,68% CPU; после — 0,05% в первом прогоне и 0,09% в финальном. В первом прогоне работа с записью занимала 1,72%, в трее — 0,44%; фоновая нагрузка машины и планировщик влияют на повторные замеры. При скрытом окне индикаторы не отправляются, WebView2 получает запрос на приостановку, аудиопоток остаётся активным.

Отдельный синтетический тест потоковой DSP-цепочки: 20 секунд обработаны за **497 мс**, на текущем потоке выделено **29 992 байта** после прогрева. Алгоритмические буферы имеют фиксированные размеры, очередь вывода ограничена 0,5 секунды, запись использует ограниченную очередь и пул массивов. Это короткий тест, не доказательство отсутствия любых долговременных утечек.

## Что не проверено

- Сквозной звук через Discord/игру: виртуальный кабель на тестовом ПК не установлен.
- Физическая loopback-задержка, длительный многосуточный прогон, субъективная естественность всех пресетов на разных дикторах.
- Все модели интерфейсов, Bluetooth-профили и драйверы Windows.
- Автоматическая установка драйвера и подписание приложения: этих функций нет.

Проверки не записывали и не отправляли голос пользователя. Тестовый WAV содержал только тишину. Пресеты проверены на сигналах; это не сертификация студийного качества на человеческой речи.

## Воспроизведение

```powershell
dotnet run --project tests/VoxLab.Tests -c Release
dotnet run --project tests/VoxLab.Windows.Tests -c Release
VoxLab.exe --diagnostics --data-dir ./diagnostics
VoxLab.exe --audio-smoke --data-dir ./audio-test
VoxLab.exe --smoke --ui-integration --exit-after-smoke --data-dir ./ui-test --screenshot ./ui.png
VoxLab.exe --performance --data-dir ./performance-test
```

`--audio-smoke` действительно открывает микрофон на три секунды, принудительно глушит выход и пишет нулевые отсчёты в диагностический WAV. `--performance` делает то же в расширенном прогоне около 100 секунд с измерением интерфейса и проверкой перезапусков. Остальные команды микрофон не открывают. `--data-dir` используется для изоляции тестовых настроек.
